# Интерактивный Claude в StealthBox

Главный агент вызывает [клиент](../scripts/stealthbox_claude.py) на компьютере с доступом по SSH к ВМ StealthBox. В локальном профиле нужны `workspace.host` и `workspace.remote_dir`. На ВМ используются штатный `stealthbox agent claude`, вход пользователя в Claude Code, tmux и Python 3. Клиент сам размещает на ВМ [обработчик задачи](../scripts/claude_task.py). Claude работает интерактивно, с обычными правами и запросами подтверждения.

Для автоматического ввода нужны tmux с полем `bracket_paste_flag` и Claude Code с командой `claude agents --json`, которая показывает состояние интерактивной сессии. Проверено с tmux 3.8 и Claude Code 2.1.330. При статусе `settling` Claude уже прислал текст через хук, но ещё занят. Дождись `answered`. При `blocked` прочитай причину в `readiness_error`.

Клиент сначала проверяет `--profile ПУТЬ`, затем `STEALTHBOX_CONFIG`, `~/.config/orchestrate/stealthbox.json` и `~/.config/stealthbox/config.json`. Для постоянного выбора рабочего профиля можно сделать `~/.config/orchestrate/stealthbox.json` ссылкой на него. Для продолжения задачи используй тот же профиль.

## Один диалог

В примере текущий каталог — каталог навыка. Выбери уникальный идентификатор задачи и сохрани его в контексте оркестратора. Путь проекта задавай относительно корня проектов на ВМ. Claude видит рабочую копию ВМ. Передавай ему контекст и границы делегированной работы.

```sh
client=scripts/stealthbox_claude.py
task=$(uuidgen)
python3 "$client" start "$task" --project team/repo < задание.txt
python3 "$client" status "$task"
```

Окно появится в сессии StealthBox. Пользователь может открыть его и продолжить диалог вручную. Проверяй состояние через `status`. Когда получишь `answered`, прочитай `answer` и запомни `turn` и `session_id`. Определи по содержанию, получил ли ты результат или Claude ждёт уточнения. После разрыва SSH сначала прочитай состояние прежней задачи. Повторяй отправку того же текста с прежним идентификатором запроса. При запросе доверия или разрешения сообщи пользователю, в каком окне Claude ждёт решения.

```sh
request=$(uuidgen)
python3 "$client" reply "$task" --request-id "$request" < уточнение.txt
python3 "$client" status "$task"
```

Уточнения идут в тот же диалог. Пока пользователь работает в этой панели, оставь ввод ему. Чтобы вернуть управление оркестратору, нужно отправить или очистить набранный текст и переключиться в другое окно либо отсоединиться от tmux.

После приёмки сохрани результат в контексте родительской задачи и сразу вызови `finish` с идентификатором принятого хода. Проверь, что статус стал `closed`. Во время фоновой работы Claude оставь окно открытым. После таймаута или смены хода заново прочитай состояние. Ручные окна и соседние панели принадлежат пользователю.

```sh
python3 "$client" finish "$task" --turn "$turn"
```

Для уточнения к закрытой задаче вызови `resume`. Откроется новое окно с сохранённым диалогом через `claude --resume`. Нужна история Claude в том же профиле и проекте на ВМ.

```sh
request=$(uuidgen)
python3 "$client" resume "$task" --request-id "$request" < продолжение.txt
```
